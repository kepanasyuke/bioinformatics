# Проект 02. Регрессионные тесты пайплайна

Пайплайн нельзя обновлять, если нечем доказать, что результат не поехал. Здесь набор
кейсов сравнивается с эталонным VCF по множеству вариантов: считаются TP, FP, FN,
precision, recall и F1. Если F1 падает ниже порога — кейс помечается регрессией,
а в CI джоба завершается с ошибкой.

```bash
python projects/02_regression/src/regression.py
```

Отчёт: [docs/report.html](docs/report.html).

## Кейсы

| Кейс | Что сломано | Ожидание |
|---|---|---|
| case_a_ideal | ничего | F1 = 1.0, проходит |
| case_b_regression | потеряны 2 варианта | recall падает, F1 < 0.95, падает |
| case_c_extra | 1 лишний вариант | precision падает, F1 ≈ 0.96, проходит |

Порог F1 — `0.95`, задан константой `THRESHOLD`.

## Функции

### `variant_key(chrom, pos, ref, alt)`
Простыми словами: делает из варианта короткую строку-ключ для сравнения.
Вход: хромосома, позиция, референсный и альтернативный аллель. Выход: строка вида `chr1:100:A>G`.

### `parse_vcf_line(line)`
Простыми словами: вытаскивает ключ варианта из одной строки VCF.
Вход: строка файла. Выход: ключ или пустая строка, если строка короткая.

### `read_vcf(path)`
Простыми словами: читает VCF и возвращает только варианты, без заголовков.
Вход: путь к файлу. Выход: список ключей.

### `compare_vcf(etalon_path, actual_path)`
Простыми словами: сравнивает два VCF и считает совпадения и расхождения.
Вход: два пути. Выход: словарь с tp, fp, fn, precision, recall, f1.

### `is_regression(f1, threshold)`
Простыми словами: решает, считать ли результат регрессией.
Вход: F1 и порог. Выход: True, если F1 ниже порога.

### `hash_file(path)`
Простыми словами: считает sha256 файла, чтобы видеть, менялся ли он.
Вход: путь. Выход: шестнадцатеричная строка.

### `vcf_text(variants)`
Простыми словами: собирает текст VCF из списка вариантов.
Вход: список вариантов. Выход: строка файла.

### `write_case(cases_dir, name, etalon, actual)`
Простыми словами: создаёт папку кейса с двумя VCF.
Вход: папка кейсов, имя, два списка вариантов. Выход: путь к папке кейса.

### `demo_cases(cases_dir)`
Простыми словами: создаёт три демонстрационных кейса.
Вход: папка. Выход: список путей.

### `list_cases(cases_dir)`
Простыми словами: перечисляет папки кейсов.
Вход: папка. Выход: отсортированный список путей.

### `case_metrics(case_dir)`
Простыми словами: считает метрики одного кейса и выносит вердикт.
Вход: папка кейса. Выход: словарь метрик с полем verdict.

### `suite_rows(cases)`
Простыми словами: делает строки таблицы для отчёта.
Вход: метрики кейсов. Выход: список строк.

### `pass_rate(cases)`
Простыми словами: считает долю пройденных кейсов.
Вход: метрики кейсов. Выход: число от 0 до 1.

### `history_rows(path)` / `write_history(path)`
Простыми словами: читает и создаёт таблицу истории по версиям.
Вход: путь к tsv. Выход: список записей или путь к файлу.

### `sections(cases, history)` / `write_report(path, cases, history)`
Простыми словами: собирают блоки отчёта и сохраняют страницу.
Вход: метрики и история. Выход: список секций или путь к файлу.

### `main(argv)`
Простыми словами: точка входа.
Вход: аргументы. Выход: код возврата.
