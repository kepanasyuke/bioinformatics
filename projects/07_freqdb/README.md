# Проект 07. База популяционных частот

Тема флагманского проекта отдела — частоты вариантов по населению. Здесь рабочий
каркас: SQLite с индексом по ключу варианта, аннотация VCF, фильтры по округам,
бенчмарк поиска и схематичная карта частот. Данные синтетические,
но запросы, схема и код настоящие — их можно навести на реальную базу.

```bash
python projects/07_freqdb/src/freqdb.py
```

Отчёт: [docs/report.html](docs/report.html). База: `data/freqs.sqlite` (пересоздаётся при запуске).

## Схема

```
variant(key TEXT PRIMARY KEY, chrom TEXT, pos INTEGER, ref TEXT, alt TEXT, af REAL, population TEXT)
```

Ключ — `chrom:pos:ref>alt` без префикса `chr`: именно из-за `chr1` против `1`
половина сравнений между базами ломается. `normalize_key` приводит оба варианта
к одной форме.

## Быстрый запрос

```bash
sqlite3 data/freqs.sqlite "SELECT population, AVG(af) FROM variant GROUP BY population;"
```

## Функции

### `normalize_key(chrom, pos, ref, alt)`
Простыми словами: приводит вариант к одному виду, убирая `chr`.
Вход: хромосома, позиция, аллели. Выход: строка `1:10000:A>G`.

### `build_db(path, rows)`
Простыми словами: создаёт базу и заливает в неё варианты.
Вход: путь и строки. Выход: путь к базе.

### `open_db(path)`
Простыми словами: открывает базу только на чтение.
Вход: путь. Выход: соединение sqlite3.

### `lookup_variant(connection, key)`
Простыми словами: ищет частоту по ключу варианта.
Вход: соединение и ключ. Выход: словарь с полями варианта или пустой словарь.

### `parse_vcf_record(line)`
Простыми словами: разбирает строку VCF по полям.
Вход: строка. Выход: словарь с chrom, pos, ref, alt, filter, info, key.

### `annotate_record(record, freq)`
Простыми словами: дописывает частоту в поле INFO.
Вход: запись и найденная частота. Выход: новая запись с `AF=…`.

### `filter_by_population(rows, population, min_af)`
Простыми словами: оставляет варианты нужного округа не реже порога.
Вход: строки, округ, порог. Выход: отфильтрованные строки.

### `iter_vcf(path)`
Простыми словами: идёт по VCF по одной записи, пропуская заголовки.
Вход: путь. Выход: генератор записей.

### `average(values)`
Простыми словами: среднее по списку.
Вход: числа. Выход: округлённое среднее.

### `demo_rows(seed, count)`
Простыми словами: делает синтетические варианты по восьми округам.
Вход: seed и число строк. Выход: кортежи для базы.

### `write_demo(data_dir, rows)`
Простыми словами: создаёт базу и файл запросов.
Вход: папка и строки. Выход: путь к базе.

### `district_rows(connection)`
Простыми словами: считает среднюю частоту и число вариантов по округам.
Вход: соединение. Выход: список строк для карты и таблицы.

### `district_tiles(rows)`
Простыми словами: превращает частоты в заливку плиток карты.
Вход: строки округов. Выход: плитки со значением 0..1.

### `af_histogram(values, bins, limit)`
Простыми словами: раскладывает частоты по корзинам.
Вход: значения и число корзин. Выход: список счётчиков.

### `time_sqlite(connection, keys, repeats)` / `time_dict(index, keys, repeats)`
Простыми словами: замеряет скорость поиска в базе и в словаре.
Вход: соединение или словарь, ключи, число повторов. Выход: миллисекунды.

### `annotate_all(connection)` / `measure(connection, rows)`
Простыми словами: аннотирует весь query.vcf и снимает тайминги.
Вход: соединение и строки. Выход: список записей или словарь таймингов.

### `summary_cards(rows, annotated, timings)` / `sections(...)` / `write_report(...)`
Простыми словами: собирают отчёт.
Вход: данные базы и тайминги. Выход: HTML-блоки или путь к файлу.

### `main(argv)`
Простыми словами: точка входа.
Вход: аргументы. Выход: код возврата.

## Что видно на скриншоте

Карта: плитки округов залиты по средней частоте, подписаны названия.
Бенчмарк: две колонки — SQLite с индексом и словарь в памяти; подпись «измерено на этой машине».
Аннотация: строка VCF до и после — видно `;AF=0.1234` в INFO.

## Ограничения

Это каркас, а не база на 120 тысяч геномов. Реальная нагрузка потребует:
партиционирования по хромосоме, Parquet вместо SQLite для аналитических срезов,
потокового чтения VCF вместо `read_text` и явных индексов под конкретные запросы.
Об этом честно написано здесь, а не только в презентации.
