# Проект 04. Бюджет кластера: где сгорают core-hours

Кластерное время — деньги. Здесь профиль из 40 задач (как будто из `sacct`) разбирается
на перерасход: сколько памяти просили «на всякий случай», сколько потоков простаивало,
и что будет, если ставить лимит по 95-му процентилю фактического пика с запасом 15%.

```bash
python projects/04_cluster_budget/src/budget.py
```

Отчёт: [docs/report.html](docs/report.html).

## Что меняется

| Шаг | Было, core-hours | Стало | Память |
|---|---|---|---|
| fastp | по запросу `--mem` | по p95 × 1.15 | 4–8 ГБ |
| bwa-mem2 | 16–24 потока | по фактической загрузке | 16–32 ГБ |
| markdup | «на всякий случай» 32 ГБ | p95 пика | 8 ГБ |
| haplotypecaller | 24 потока | по загрузке | 16 ГБ |
| bcftools | 8 потоков | по загрузке | 4 ГБ |

Правило расчёта потоков: `suggest_cpus` берёт фактическое потребление CPU
(`TotalCPU / Elapsed`) и округляет вверх, но не ниже единицы.

## Функции

### `parse_mem(value)`
Простыми словами: переводит строку из sacct вида `4Gn` в мегабайты.
Вход: строка. Выход: целое число мегабайт.

### `format_mem(megabytes)`
Простыми словами: показывает мегабайты по-человечески.
Вход: число. Выход: строка «4.0 ГБ» или «512 МБ».

### `usage_ratio(used, requested)`
Простыми словами: считает, какую долю лимита реально заняли.
Вход: пик и лимит. Выход: число от 0 до 1.

### `percentile(values, share)`
Простыми словами: считает процентиль с линейной интерполяцией.
Вход: список чисел и доля (0.95). Выход: число.

### `suggest_mem(values)`
Простыми словами: предлагает лимит памяти по пику с запасом и округлением до 512 МБ.
Вход: список пиков. Выход: число мегабайт.

### `cpu_efficiency(job)`
Простыми словами: считает, насколько задача загрузила выданные потоки.
Вход: запись задачи. Выход: доля от 0 до 1.

### `suggest_cpus(job)`
Простыми словами: предлагает число потоков по фактической загрузке.
Вход: запись задачи. Выход: целое число, не меньше единицы.

### `core_hours(cpus, minutes)`
Простыми словами: переводит потоки и минуты в core-hours.
Вход: потоки и минуты. Выход: число.

### `mean(values)`
Простыми словами: среднее по списку.
Вход: список чисел. Выход: округлённое среднее.

### `demo_jobs(seed, count)`
Простыми словами: делает синтетический профиль задач.
Вход: seed и число задач. Выход: список записей.

### `summarize(jobs)`
Простыми словами: сворачивает задачи по шагам пайплайна.
Вход: список задач. Выход: список строк по шагам.

### `savings(before, after)`
Простыми словами: считает процент экономии.
Вход: два числа. Выход: процент.

### `worst_rows(jobs, limit)`
Простыми словами: выбирает самые расточительные задачи.
Вход: задачи и сколько показать. Выход: строки таблицы.

### `scatter_points(jobs)`
Простыми словами: готовит точки для графика «запрошено против использовано».
Вход: задачи. Выход: список точек с группой.

### `heatmap_values(rows)` / `savings_share(row)`
Простыми словами: считают доли полезного использования для тепловой карты.
Вход: строки по шагам. Выход: матрица чисел 0..1 или одно число.

### `summary_cards(jobs, rows)`
Простыми словами: собирает четыре верхние плитки отчёта.
Вход: задачи и строки по шагам. Выход: HTML.

### `sections(jobs, rows)` / `write_report(path, jobs, rows)`
Простыми словами: собирают и сохраняют отчёт.
Вход: задачи и сводка. Выход: список секций или путь к файлу.

### `main(argv)`
Простыми словами: точка входа.
Вход: аргументы. Выход: код возврата.

## Что видно на скриншоте

Скаттер: облако точек внизу графика — это задачи, которым просили 32 ГБ при пике 7 ГБ.
Столбики «до/после»: экономия по каждому шагу отдельно, суммарно −40…−50%.
