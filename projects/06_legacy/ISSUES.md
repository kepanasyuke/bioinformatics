# Чужой пайплайн: десять багов

Файл до исправления: [`legacy/broken_pipeline.sh.orig`](legacy/broken_pipeline.sh.orig).
Файл после: [`src/fixed_pipeline.sh`](src/fixed_pipeline.sh).
Каждый баг — отдельный issue с объяснением простыми словами. Проверка: `bash -n` и `shellcheck`.

| № | Баг | Чем плохо | Как исправлено |
|---|---|---|---|
| B1 | нет `set -euo pipefail` | падение шага проглатывается, пайплайн «успешно» завершается | добавлены три опции в начале |
| B2 | `for f in $(ls *.fastq)` | имена с пробелами ломаются, `ls` не нужен | `find -print0` + `while IFS= read -r -d ''` |
| B3 | `cd $DIR` без кавычек и проверки | при пустой переменной уводит в `/`, дальше всё удаляется не там | `cd` убран, пути абсолютные, `DATA_DIR` проверяется через `require_var` |
| B4 | `continue` в глубине четырёх `if` | логика нечитаема, ошибку легко пропустить | `continue` нет, условие инвертировано в `if/else` |
| B5 | `return` в трёх ветках `check_vcf` | три выхода из функции, непонятно, какой сработал | один `return "$status"`, код в переменной |
| B6 | вложенность 5 | невозможно проверить глазами | максимум 3, остальное вынесено в `process_sample` |
| B7 | `rm -rf $TMP/` без кавычек | при пустом `TMP` удаляет `/` | `safe_rm_dir` отказывается удалять пустое и `/` |
| B8 | общий `/tmp/pipe` на все образцы | два параллельных запуска затирают файлы друг друга | `tmp_dir_for` даёт каталог на образец |
| B9 | коды возврата `bwa` и `samtools` не проверяются | битый BAM уезжает дальше как валидный | `check_exit` и явные `|| status=N` |
| B10 | `grep -q PASS` вместо разбора VCF | считает строки с PASS в INFO, а не варианты | `parse_vcf_line` режет строку по табам |

## Почему это не косметика

B7 и B3 вместе — это классический способ потерять данные на кластере: переменная
не пришла из очереди, `rm -rf` получил пустой путь. B8 даёт «плавающие» результаты,
которые невозможно воспроизвести. B1 + B9 превращают любую ошибку инструмента
в молчаливый пропуск образца, и об этом узнают через месяц по странной статистике.
