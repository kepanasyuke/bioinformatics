# Правила стиля

Восемь правил, одинаковых для Python и bash во всех проектах репозитория.
Проверяются `tools/check_style.py`, для bash дополнительно `shellcheck`.

## 1. Один выход из функции

В функции ровно один `return`, и он последний. В bash — ровно один `return`
или единственный `break` из `while :; do … done`.

```python
def count_passing(scores, min_score):
    passing = 0
    for score in scores:
        if score >= min_score:
            passing += 1
    return passing
```

```bash
run_pipeline() {
    local status=0
    while :; do
        if ! check_inputs; then status=1; break; fi
        if ! build_index; then status=2; break; fi
        break
    done
    return "$status"
}
```

`while (1)` и `while (0)` — легальный единственный выход. `return` внутри `if` — нет.

## 2. Никаких `continue`

Условие инвертируется, тело переносится в `else`, либо фильтр выносится в отдельную функцию.

```python
def iter_passing(records, min_q30):
    for record in records:
        if record.q30 >= min_q30:
            yield record
```

## 3. Вложенность не глубже трёх

Считаются `for`, `while`, `if`, `with`, `try` внутри функции. Если не влезает —
значит из тела пора выделить функцию. Линтер считает это автоматически.

## 4. Функция делает одно действие

Тело — до двенадцати строк по линтеру, на практике одна-две строки. Имя функции
отвечает на вопрос «что делает», а не «как устроено».

## 5. Описание простыми словами

В README каждого проекта есть раздел «Функции»: одна строка «что делает»,
отдельно вход и выход. Без жаргона и без «валидирует DTO».

## 6. Данные отдельно от логики

Пути, пороги и версии — в `data/*.json` или `data/*.tsv`. В коде нет магических чисел,
кроме геометрии графиков.

## 7. Воспроизводимость

Каждый отчёт собирается командой `make reports`. Случайные данные — только через
`random.Random(seed)` с фиксированным seed, чтобы скриншот совпадал с повтором.

## 8. Честные подписи

Синтетические данные помечаются словом «синтетические» в заголовке отчёта.
Никаких выдуманных чисел, выданных за реальные измерения.

## Как проверить

```bash
python tools/check_style.py .
shellcheck projects/*/src/*.sh
```

Оба вызова стоят в CI: `.github/workflows/ci.yml` и `.gitlab-ci.yml`.
